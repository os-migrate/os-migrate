Role - import_from_hypervisor

Role Documentation

Import From Hypervisor Role

This role spawns nbdkit on OpenStack hypervisors (compute nodes) for workloads that have use_nbdkit_direct: true in their migration parameters.

Purpose

This role is part of the nbdkit direct mode migration workflow. It:

  1. Reads workloads from workloads.yml
  2. Filters workloads with use_nbdkit_direct: true
  3. For each workload:
  4. Connects to the hypervisor (from hypervisor_hostname in workload data)
  5. Finds the instance disk
  6. Inspects disk format (qcow2 vs raw) and detects backing files
  7. Spawns nbdkit with the correct plugin
  8. Updates the workload file with the nbdkit URI

Workflow Order

1. export_workloads.yml # Exports workloads with hypervisor_hostname 2. import_from_hypervisor.yml # Spawns nbdkit (this role) 3. import_workloads.yml # Migrates using nbdkit URIs

Required variables

In nbdkit direct mode each disk is streamed straight from the hypervisor's qemu-nbd, so no source conversion host is used. For the workflow to run correctly you must disable the source conversion host in the deploy and import steps, otherwise the playbooks try to create, link or wait for an os_migrate_conv_src that does not exist and fail.

Set the following variables (in your vars.yml or via -e):

| Variable | Value | Effect | | --- | --- | --- | | os_migrate_deploy_src_conversion_host | false | deploy_conversion_hosts.yml deploys only the destination conversion host, not a source one. | | os_migrate_link_conversion_hosts | false | Skips the conversion-host link step, which otherwise waits for a source conversion host to become reachable over SSH. | | os_migrate_requires_src_conversion_host | false | import_workloads.yml does not require a source conversion host; a missing os_migrate_conv_src is tolerated instead of failing the run. |

```yaml

vars.yml

os_migrate_deploy_src_conversion_host: false os_migrate_link_conversion_hosts: false os_migrate_requires_src_conversion_host: false ```

Only the destination conversion host is required in this mode.

Hypervisor connection

The role delegates the qemu-img / qemu-nbd tasks to the hypervisor using delegate_to: "{{ hypervisor_hostname }}", so the SSH user and other connection settings are taken from the hypervisor's inventory entry (ansible_user / ansible_ssh_user). Make sure the compute node reported by nova as hypervisor_hostname is present in your inventory with the right credentials.

If you cannot (or do not want to) add the hypervisor to the inventory, set os_migrate_hypervisor_ssh_user to override the SSH user used for the delegated tasks (e.g. root or stack). Leaving it empty keeps the inventory settings.

Usage

```bash

1. Export workloads

ansible-playbook export_workloads.yml -e os_migrate_data_dir=/data

2. Spawn nbdkit on hypervisors

ansible-playbook import_from_hypervisor.yml -e os_migrate_data_dir=/data

3. Import workloads

ansible-playbook import_workloads.yml -e os_migrate_data_dir=/data ```

See full README in the file for more details.

Role Defaults

This section highlights all of the defaults and variables set within the “import_from_hypervisor” role.

# Defaults for import_from_hypervisor role

# SSH user for connecting to the source hypervisor(s).
# Leave empty (default) to use the connection settings defined for the
# hypervisor host in your inventory (recommended). Set it to override the SSH
# user used for the delegated qemu-img / qemu-nbd tasks (e.g. 'root', 'stack').
os_migrate_hypervisor_ssh_user: ''

# NBDkit configuration
os_migrate_nbdkit_port: 10809
os_migrate_nbdkit_protocol: tcp  # 'tcp' or 'ssh'

# Max simultaneous NBD clients qemu-nbd accepts per disk (qemu-nbd -e/--shared).
# The export is read-only, so multiple connections are safe and let nbdcopy copy
# a disk over several parallel streams (big win for large, incompressible disks).
# Without this qemu-nbd defaults to 1, capping nbdcopy to a single connection.
# Set to 0 for unlimited.
os_migrate_nbdkit_shared_connections: 8
os_migrate_nbdkit_ssh_user: stack
os_migrate_nbdkit_readonly: true
os_migrate_nbdkit_timeout: 300

# IP restriction (optional) - set to destination conversion host IP
os_migrate_nbdkit_ip_allow:

# Nova directories on hypervisor
os_migrate_nbdkit_nova_instances_dir: /var/lib/nova/instances
